# Изменения

## 1.0.3 — 2026-11-06

Оформление «как Hermes», исправления по итогам реальной работы и несколько новых возможностей.

**Оформление и удобство**
* Вид приведён к Hermes Desktop: базовый шрифт 14 px, шрифты Hermes (JetBrains Mono в комплекте), цвета и тема подхватываются у хозяина через модуль; светлая и тёмная темы, контраст ≥ 4,5:1.
* Карточка участника стала компактной: имя и должность, одна строка «Сейчас…», один чип модели, меню «⋯», ссылка «Особенности (N)». Подпись можно задать у всех, включая руководителя и критика.
* «Следующие шаги» читаются: шаг занимает одну строку, подробности — в окне шага. Правая колонка запроса — сворачиваемые блоки, «Нужен ваш ответ» всегда сверху; таблицы свода больше не вылезают.
* Названия запросов формируются осмысленно (штатным генератором Hermes) вместо сырого куска диктовки, меняются по ходу беседы; переименовать можно карандашом.
* Окно «Особенности для этой комнаты» стало полноценным блокнотом: записи, поиск, диктовка, журнал и откат.

**Исправлено**
* Страница запроса не «улетает» вверх при обновлении: прокрутка, фокус и черновики сохраняются; после перезагрузки окна открывается то же место.
* Вкладка «Дальше» больше не просит повторно ответить на вопросы, на которые вы уже ответили; одинаковые вопросы склеиваются.
* «Напомнить руководителю» больше не отвечает «уже ответил» без самого ответа; реакция руководителя ищется одним способом везде.
* «Нерасшифрованная запись» после «Убрать» больше не возвращается; обрыв микрофона замечается и не теряет надиктованное.
* Этапы проекта — свойство комнаты, а не зашитый список; ссылка «Включить проектный режим» открывает настройки текущей комнаты, режим объяснён простым языком.
* Один «свод»: единая кнопка «Доработать свод», предпросмотр того, что получит руководитель, ответы и уточнения передаются автоматически, версии подписаны причиной и списком изменений.

**Служебное**
* Сервер отдаёт меньше данных (меню — одним запросом, без записей «Признак жизни»); предпросмотр «Проверить доску сейчас» читается без записи.

**Свод команды стал понятным: одна кнопка доработки, предпросмотр отправки и версии с причиной.**
Михаил спрашивал: чем отличаются две кнопки «На доработку», перечитывается ли диалог, учтутся ли
его ответы на вопросы и что вообще изменилось в версии 2. Теперь:
* **«Доработать свод» — единственная кнопка** (в блоке «Свод команды»). В диалоге ленты второй
  одноимённой кнопки нет; там под полем — переключатель «и доработать свод по этому сообщению»
  (сообщение уходит как уточнение и этим же текстом запускает доработку).
* **Предпросмотр «Что получит руководитель»** — прямо в окне доработки: запрос, свод версии N,
  ваше замечание и «3 ответа на вопросы и 3 уточнения после версии 3» (раскрывается список
  вопрос → ответ). Честная строка: весь диалог целиком не пересылается.
* **Автодайджест в карточке доработки.** `contract.revision_digest` собирает ответы Михаила на
  вопросы (со статусом реакции руководителя), его уточнения в диалоге (полный текст), новые решения
  и шаги, которые он согласовал, переместил или убрал, — с момента выпуска текущей версии;
  `build_revision_body` вставляет это блоком
  `<<<ПОСЛЕ ВЕРСИИ N (это уже произошло — учти ВСЁ)>>>` и требует `metadata.changes` /
  `metadata.version_reason`. Пустое замечание больше не блокирует доработку: без своего текста
  уходит понятная фраза «Доработать свод с учётом моих ответов…».
* **Версии подписаны причиной:** «Версия 1 — первый свод», «Версия 2 — доработка по вашему
  замечанию: «…»», «Версия 3 — после ваших ответов и уточнений (3)». Рядом «Что изменилось»
  (3–7 пунктов руководителя из `metadata.changes`, запасной путь — разница по разделам) и
  необязательное сравнение с предыдущей версией (зелёное — добавлено, красное — удалено).
  `synthesis.history[]` получил поля `reason`, `answers_count`, `changes`; причина версии хранится
  в реестре запроса (`extra_cards.note/reason`), данные на диске не переписываются.
* **Отметка «свод устарел»:** «После версии 3 есть 3 ваших ответа и 3 уточнения — в своде это ещё
  не учтено» + кнопка «Доработать с учётом ответов» (то же действие `revise`, дайджест собирается
  сам). После доработки строка исчезает.

**«Дальше» знает об ответах.** Вопрос, на который Михаил ответил, больше не висит в «ждут вашего
решения». Статус вопроса в бэклоге, в счётчиках вкладки и на странице запроса считается из одного
источника — реестра ответов — и пересчитывается сразу после ответа, без ожидания прохода плана.
Вопросы-близнецы (руководитель выдал тот же вопрос с новым id) схлопываются в один элемент со
списком `aliases`, счётчики считаются по уникальным. Служебный вопрос «сколько раундов критика»
(hidden) не показывается ни в запросе, ни в «Дальше», ни в бейдже. Данные на диске не переписываются.
* **Встречный вопрос — только по кнопке.** «Мне нужно пояснение» остаётся надёжным путём; текст
  «поясни, что это» без кнопки считается ответом — прошлая версия ошибочно держала такой вопрос
  открытым на старых записях (боевой `q_7985e685`).
* **Накопленные ответы одной карточкой.** Кнопка «Отправить руководителю накопленные ответы»
  (`answers_resend`) присылает руководителю одно сообщение и одну карточку со всеми ответами без
  реакции, по порядку вопросов; сама, без клика, ничего не отправляет.
* **Страница запроса легче втрое на поллинге.** `timeline` без «признаков жизни» (только счётчик
  `heartbeats`), дубль `questions` убран, в дереве работ нет копий свода/метаданных в каждой попытке,
  добавлен `?fields=` для выборки блоков. Боевой ответ: 272 → 199 КБ, набор для опроса — 92 КБ.
* **Одно чтение на боковое меню.** `GET /api/rooms/summary` отдаёт счётчики и последние запросы всех
  комнат одним ответом; предпросмотр «Проверить доску сейчас» — `GET /api/dispatcher/preview`, без POST.
* **Названия запросов — как в Hermes Agent.** В «Недавнем», списке, крошках и шапке вместо сырой
  диктовки — короткое понятное название ≤ 60 знаков. Мгновенное (`derived`) появляется сразу при
  создании, затем в фоне уточняется одним вызовом малой модели штатным генератором Hermes
  (`agent/title_generator.py`, `auxiliary.title_generation` — какая модель настроена у пользователя,
  та и работает; мост `tools/title_bridge.py`). Название следует приоритету источников
  `derived < llm < leader < user`: `metadata.title` руководителя сильнее модели, а заданное
  пользователем (`PATCH /api/requests/{id}`, «карандаш» в шапке) не перезаписывается никогда
  (`title_source="user"`, `title_locked=true`; пустое значение снимает блокировку). По ходу беседы
  название пересчитывается после выпуска свода и после существенных уточнений — не чаще раза в
  5 минут. Нет Hermes/модуля/модели или мост завис — остаётся мгновенное название; создание
  запроса не блокируется.
* **«Напомнить руководителю» больше не врёт «уже ответил».** Реакция ищется одной функцией и для
  окна вопроса, и для кнопки: только от руководителя комнаты и только ПОСЛЕ ответа (боевой случай
  `q_7decf20e`: комментарий 16:48 засчитывался реакцией на ответ 16:52). Порог запасного
  сопоставления по словам поднят и требует доли от текста вопроса. Если реакция действительно
  есть, `409` приходит ВМЕСТЕ с ответом и найденной реакцией — окно показывает их, а не пустое
  «руководитель уже ответил».

**Карточка участника стала компактной — и подпись есть у всех.**

* **Одна карточка — один взгляд.** На лице: аватар, имя и должность, роль-бейдж, статус-точка,
  одна строка «Сейчас: …» (или «свободен»), ОДИН чип выбранной модели и ссылка
  «Особенности (N)» → большое окно-блокнот. «Последняя», «готово N», «роль фиксирована» и имя
  профиля убраны с лица — они в раскрытии «Подробнее» и в подсказках. Действия — в меню «⋯»:
  «Изменить модель», «Подпись», «Роль в комнате…», «Убрать из комнаты» (последнее — только у
  обычных исполнителей). «Ушло на: …» исчезло: предупреждение «Последний запуск шёл на другой
  модели — проверьте» появляется ТОЛЬКО когда последняя карточка участника действительно ушла не
  на выбранную модель, и раскрывает подробности по кнопке.
* **Подпись у руководителя и критика (B-17).** Раньше «Подпись» была только у исполнителей, а
  сервер отвечал руководителю отказом `room_lead` («задаётся в настройках комнаты», где такого
  поля не было). Теперь у всех участников один и тот же набор действий, а подпись руководителя и
  критика хранится в реестре комнаты (`role_labels`), не меняя профиль Hermes. Приоритет:
  подпись в комнате → описание профиля (`hermes profile describe`) → описание из `profile.yaml` →
  роль. Поэтому у профилей без описания в заголовке не техническое `default`/`lawyer`, а
  «Руководитель комнаты»/«Исполнитель» плюс мягкая ссылка «Задайте подпись».

**Оформление «как Hermes».**

* **Базовый кегль 14 px** (как `text-sm` в Hermes Desktop) и шкала 12 / 14 / 16 / 18–20 / 22–24,
  межстрочный 1.5; гарнитура `Segoe WPC → Segoe UI → system-ui`, моно — `JetBrains Mono`
  (файл из пакета Hermes, OFL-1.1, `web/fonts/`); скругления 8–12 px, управления под 14 px.
  Читаемого текста мельче 12 px нет: 11 px — только счётные бейджи и буквы в аватарах.
* **Окно комнаты перенимает тему приложения-хозяина**: плагин читает вычисленные токены
  (поверхности, текст, штрихи, акцент, радиус) и передаёт их странице; светлая/тёмная схема
  следует за Hermes без перезапуска. Пары цветов с контрастом ниже 4.5:1 не применяются —
  остаются наши проверенные значения.
* **«Особенности для этой комнаты» — большое окно-«блокнот».** Маленькое поле в карточке
  участника не вмещало длинные инструкции. Теперь записи открываются в отдельном окне
  (≈80% экрана, на узком — на весь экран): слева список с поиском и фильтром
  «все / ваши / руководителя», справа — редактор записи на всю высоту с «Надиктовать»
  и «Сохранить»; внизу «Новая запись», «Закрепить», «Удалить», «Сократить», «Журнал»
  с «Откатить» и счётчик «N из 24 записей · M из 8000 знаков». В карточке и в диалоге
  комнаты осталась только ссылка «Особенности (N)». Esc закрывает (с подтверждением
  несохранённого), Ctrl+S сохраняет, фокус заперт в окне.

**Шаги одной строкой и аккордеоны справа (правая колонка запроса).**

* **Шаг — одна строка.** Раньше текст шага попадал в колонку 15 px (осталась от убранной галочки):
  строка растягивалась на 900–1300 px и читалась по буквам, а блок из 5 шагов занимал 5 194 px.
  Причина была двойная — сетка и то, что стили блока подключались только в «Дальше» и в окне шага.
  Теперь шаг — одна строка: иконка статуса, название с обрезкой в две строки (полный текст — в
  подсказке), аватар исполнителя с подписью и короткий срок («10 ноя», «сегодня», «просрочен»).
  Блок из 10 шагов — около 620–675 px (было 5 000+ на пяти). Подробности — в окне шага, как раньше.
* **Правая колонка — аккордеоны.** «Нужен ваш ответ (N)» закреплён сверху и всегда раскрыт; ниже
  «Отвечено», «Шаги», «Решения», «Будущие вопросы», «Карта проекта» свёрнуты до заголовка со
  счётчиком. Состояние запоминается (`localStorage`), в том числе после перезагрузки.
* **Один счётчик на всех экранах (B13).** Число и расшифровка («2 вопроса · 1 блокировка ·
  1 решение») считаются той же функцией, что бейдж вкладки «Дальше» (`inboxSummary`,
  `blockedCards`); предложенное решение видно в списке, а не только в числе.
* **Меньше шума в формах.** У каждого вопроса остались поле, «Отправить» и короткая «Пояснить…»,
  а объяснение («Мне нужно пояснение — руководитель объяснит, вопрос останется открытым») написано
  один раз над списком. Статус ответа — чип, который ужимается, а не вылезает из карточки.
* **Досылка накопленных ответов.** Кнопка «Отправить руководителю накопленные ответы»
  (`answers_resend`) появляется, только когда есть ответы без реакции руководителя, и показывает
  их число. Только по нажатию — это запускает руководителя.
* **«Напомнить» больше не спорит с реальностью (B-12).** Если руководитель уже ответил (сервер
  отвечает `409` вместе с реакцией), реакция сразу появляется у вопроса, а кнопка напоминания
  исчезает — вместо пустого окна и подписи «руководитель ещё не ответил».
* **Таблицы «Свода» не вылезают (B3).** Ячейки переносят слова (раньше `nowrap` — таблица уходила
  за карточку на 600–1 136 px), длинные пути рвутся по `overflow-wrap: anywhere`, а обёртка
  прокручивается вбок с тенью-подсказкой с той стороны, где есть продолжение. Блоки кода —
  с собственной прокруткой. Позиция прокрутки таблицы переживает обновление страницы.

**Страница запроса больше не «улетает» вверх.**
* **Обновление без пересборки.** Пока команда работает, данные меняются каждую минуту, и страница
  перерисовывалась целиком: правая колонка «Дальше» (до 9 000 px) и лента диалога (до 7 000 px)
  каждый раз стартовали с нуля. Теперь изменившиеся блоки заменяются точечно (`web/js/live-patch.js`):
  совпавшие узлы остаются на месте, шаги, вопросы, решения и сообщения сопоставляются по
  `data-key`/`data-id`. Прокрутка обеих колонок, фокус, выделение, раскрытые блоки и черновики
  сохраняются — измерено на длинном запросе (12 шагов, 10 вопросов, 40 сообщений, 90 событий).
* **Пока печатают или диктуют — не трогаем.** Если курсор в поле ответа или идёт запись голоса,
  обновление откладывается и применяется сразу после ухода из поля: набранный текст не исчезает
  и не «перескакивает».
* **Heartbeat не перерисовывает.** События «Признак жизни» не считаются изменением экрана —
  страница не мигает и не сбрасывает позицию каждую минуту.
* **Опрос реже.** Деталь запроса — раз в 5 с (было 2 с), завершённый запрос — раз в 30 с; в скрытой
  вкладке опрос стоит, при сбоях связи сам замедляется. Боковое меню: один `GET /api/rooms/summary`
  вместо пачки запросов по всем комнатам; «Недавнее» и числа вопросов — не чаще раза в минуту.

**Названия запросов везде короткие, а не сырая диктовка.**

* Заголовок страницы, крошки, «Недавнее» в боковом меню, список запросов и вкладка «Дальше»
  показывают короткое название (≤ 60 знаков); полный текст диктовки — в подсказке к названию
  (и в блоке «Запрос» на странице). Обрезок без подсказки не осталось.
* **Переименование карандашом** в шапке запроса: правка на месте, `Enter` сохраняет, `Esc` отменяет,
  без перезагрузки и без потери прокрутки. Сохранённое название помечается замком («ваше название»):
  автоматика его не перезаписывает, клик по замку возвращает автоматическое.
* Название, пересчитанное сервером (`llm`/`leader`), появляется на экране само — без «Загружаю…»
  и без мигания: пока идёт улучшение, видно мгновенное название.
* **«Недавнее» — одним запросом** (`GET /api/rooms/summary`): короткие названия и название комнаты
  мелкой строкой, вместо пачки запросов по всем комнатам.

**Вкладка «Дальше» не спрашивает одно и то же дважды.**

* Ответили на вопрос — строка исчезает сразу, число у вкладки и в сайдбаре уменьшается в тот же
  момент, без перезагрузки и без ожидания прохода плана.
* Один вопрос — одна карточка: близнецы с разными номерами схлопываются, ответ на любой закрывает
  оба; служебные вопросы («сколько раундов критика») не показываются.
* Форма ответа одна на два экрана (та же, что в правой колонке запроса): поле, «Отправить»,
  «Мне нужно пояснение»; длинное объяснение написано один раз над списком, а не под каждой строкой.
* **Счётчики с пояснением:** подсказка у числа говорит, что считается («вопросы без вашего ответа,
  заблокированные задачи и предложенные решения»), а «выполнено N из M» — что N работ из M.
* **Загрузка — заглушки в форме будущих карточек** и честная подпись «Загружаю…» вместо серых полос
  и «0»; появляются только если ответ задерживается, и снимаются сразу, как пришли данные.

**«Карта проекта» говорит о СВОЕЙ комнате: этапы — её свойство, а не чужая константа.**

* **Этапы проекта больше не зашиты в код.** Раньше «Карта проекта» показывала всем комнатам
  один и тот же список из шести этапов одного проекта (константа `PHASES` в трёх местах) —
  в юридическом управлении висели «Упаковка», «Производство», «Продажи». Теперь у комнаты
  необязательное поле `phases: [{id, title}]`, а списка этапов в коде нет вовсе (портативность:
  продукт для любых людей). У новой комнаты и у «Руководства_FN» этапов нет — нет ни полосы
  этапов, ни чипа этапа в шапке, ни блока «где мы сейчас».
* **Этапы правятся в настройках комнаты:** добавить, переименовать, переставить стрелками,
  удалить; лимиты 24 этапа / 80 знаков; шаблонов по умолчанию не бывает. Данные привязаны к
  `id`, поэтому переименование и порядок ничего не ломают.
* **Миграция чтением:** у комнаты, которая уже вела карту (в `data/state/<комната>/roadmap.json`
  есть статусы кроме «впереди», заметки или запрос-источник), этапы подхватываются из её же
  файла как её собственные — данные не переписываются. Пустая заготовка «шесть строк впереди»
  данных не даёт: этапов не появляется.
* **Ссылка «Включить проектный режим» открывает настройки ТЕКУЩЕЙ комнаты** (диалог в режиме
  правки, с прокруткой на раздел «Проектный режим»), а не диалог создания новой комнаты:
  заголовок «Комната: …», поле названия заполнено, кнопка «Сохранить». После сохранения карта
  обновляется без перезагрузки.
* **Проектный режим объяснён по-человечески:** «большой запрос руководитель делит на несколько
  частей работы (например: «юридическая часть», «закупки», «упаковка»). Каждая часть — отдельный
  запрос со своим ходом работы и своим исполнителем». Единый термин вместо «направления» —
  «часть работы» (диалог, карта, журнал плана, подписи интерфейса). У каждой настройки —
  строка-пояснение с примером, у раздела — состояние словами («Сейчас: включён/выключен»).
* **Решения Михаила:** новые комнаты запускают части сразу, без подтверждения (`launch_mode=auto`),
  одновременно по умолчанию 2; настройки существующих комнат НЕ меняются (записи без поля
  читаются как «сначала план»).

  (готово / в работе / не начат / ждёт решения).

## 1.0.2 — 2026-11-05

Исправления и доработки по итогам первого использования.

**Главное**
* **Запросы идут на выбранную модель.** Карточки, которые создаёт руководитель при разбивке задачи,
  раньше уходили на модель профиля. Теперь выбор участника применяется ко всем карточкам комнаты
  (контракт руководителя, перехват по комнате, перезапуск стартовавшей на не той модели, сверка с
  фактом из сессии воркера). В карточках видно «ушло на: провайдер · модель» и пометку
  «расходится с выбором комнаты».
* **Длинная диктовка не теряется.** Лимит записи берётся из настроек Hermes (не менее 10 минут);
  запись режется на части и сразу сохраняется на диск, при лимите или обрыве уходит на
  распознавание сама, есть «Распознать ещё раз» и восстановление после закрытия страницы.
* **«Есть нерасшифрованная запись» больше не возвращается.** Строка про несохранённую запись
  появляется только тогда, когда звук действительно есть; пустые «хвосты» (микрофон отвалился, и
  записать ничего не успели) не заводятся и вычищаются — раньше каждая сорванная попытка добавляла
  ещё один такой след, поэтому «Распознать» отвечал «не удалось», а надпись возвращалась после
  «Убрать». Теперь «Убрать» убирает и след, и серверную копию, а запись, которой уже нет на диске,
  не висит вечно. Если записей несколько, строка честно говорит «записи: 2 · 8:29» и убирает
  их разом («Убрать все»).
* **Микрофон отвалился — видно и не теряется.** Запись останавливается сама (панель не висит в
  «Запись» с бегущим таймером), сказанное до этого уходит на распознавание, а если записать ничего
  не успели — понятное сообщение вместо «Речь не обнаружена»: «Микрофон отключился…».
* **Ответ — это ответ на конкретный вопрос.** Вопрос и ответ показываются вместе, у ответа виден
  статус (отправлен → принят → учтён) и реакция руководителя, есть «Напомнить руководителю» и
  «Мне нужно пояснение»; встречный вопрос больше не закрывает вопрос; шаг, противоречащий ответу,
  снимается или помечается.
* **«Следующие шаги»** — план руководителя без галочек: клик открывает окно шага с действиями
  «Согласен», «Прокомментировать», «Переместить», «Не согласен — убрать».
* **Критик:** понятное объяснение и единое слово «раунд»; руководитель не переспрашивает число
  раундов; новый режим «До полного одобрения» со страховками (стоп при зацикливании, пауза при

  обращения к распознаванию — запись не дошла до сервера. В интерфейсе было два пути, которые
  уничтожали её молча: `pagehide` (окно модуля закрыли, страницу перезагрузили) вызывал «отмену»
  и выбрасывал уже наговоренное, а таймаут запроса распознавания в 120 секунд обрывал его без
  сообщения и без повтора. Плюс сама запись шла одним файлом в памяти страницы — при обрыве
  восстанавливать было нечего.
* **Лимит записи — из настроек Hermes**, своих больше нет: сервер читает
  `voice.max_recording_seconds` из `config.yaml` (только чтение) и отдаёт в `/api/stt/status`
  (`max_recording_s`, `part_seconds`); меньше 10 минут лимит не опускается. Панель показывает
  фактический предел («0:07 / 15:00»).
* **Запись режется на части по 2 минуты.** Каждая часть — отдельный файл: сразу на диск сервера
  (`data/stt-recordings/<rid>/part-0001.webm`) и в IndexedDB браузера, и только потом на
  распознавание. Обрыв одной части не убивает остальные.
* **Ничего не теряется**: при достижении лимита запись сама уходит на распознавание; при ошибке
  сети или сервера остаётся кнопка «Распознать ещё раз»; при закрытии окна/перезагрузке части уже
  на диске, а в панели появляется «Есть нерасшифрованная запись · 6:12» → «Распознать запись».
  `Esc`/«Отмена» — единственный способ удалить наговоренное.
* **Прогресс и свободное поле**: части распознаются по очереди, рядом с полем «Распознано 3 из 7
  минут»; поле не блокируется, текст вставляется по мере готовности частей.
* **API:** `GET /api/stt/status` дополнен `max_recording_s`, `max_recording_source`,

Пакет H — пункт 12:
«Следующие шаги» — план руководителя, а не чек-лист пользователя; действия по шагу уходят ответом на шаг.

* **Галочек у пользователя больше нет.** Статус шага (предстоит / в работе / сделано / снят) ведут
  руководитель и система по факту готовых карточек; выполненные отделены («Сделано»), предстоящие —
  «Дальше», снятые — «Снято». Подпись блока: «План руководителя на ближайшее время. Можно поправить
  любой шаг». Срок в строке больше не правится на месте — только через окно шага.
* **Окно шага (модальное, доступно с клавиатуры):** что за шаг, исполнитель с подписью профиля
  (`participantLabel`, пакет G) и срок, **зачем нужен** (вопрос/ответ-источник, `question`/`answer`),
  статус, история (`history`), метка «противоречит вашему ответу».
* **Действия:** «Согласен» (`step_agree`), «Прокомментировать» с диктовкой (`step_comment`),

  Любое действие уходит руководителю **как ответ на этот шаг**: метка в ветке
  `[Михаил · … шаг ns_x «…»]`, запись `step_actions`/`steps_log` в реестре, видимая реакция
  «принято / учтено / срок изменён / порядок изменён / шаг убран», а до реакции — «руководитель ещё
  не ответил». Реакция руководителя читается из `[Руководитель · реакция на шаг ns_x] …`.
* **«Дальше» и «Карта проекта»** — тот же принцип: строка шага открывает то же окно
  (`web/js/views/step-dialog.js`); чекбокс из вкладки «Дальше» убран.
* **API:** новые действия `step_agree`, `step_comment`, `step_move`; `NextStep` дополнен

Пакет D — пункты 5, 6, 10:
ответ на вопрос стал ответом НА ВОПРОС, с видимой реакцией руководителя и без противоречащих шагов.

* **Ответ связан с вопросом.** `POST …/actions {action:"answer"}` сохраняет связку
  `question_id ↔ answer` в реестре комнаты и пишет в ветку отдельную запись
  `[Михаил · ответ на вопрос q_x «текст вопроса»] …`; в ленте это `kind="answer"` со ссылкой на
  вопрос (`question_id`, `question_text`), а не обычное сообщение. Руководитель получает ответ
  рабочей карточкой «Уточнение» с контрактом реакции.
* **Статус ответа и реакция руководителя.** `sent → received → applied → no_change`: руководитель
  отвечает короткой реакцией в ветке `[Руководитель · реакция на ответ q_x] Принято: …` /
  `Работа пересмотрена: карточки t_…` / `…ничего менять не нужно`, она видна у вопроса. Пока
  реакции нет — «руководитель ещё не ответил» и кнопка «Напомнить руководителю»
  (`action:"answer_remind"`).
* **Встречный вопрос не закрывает вопрос.** Явная кнопка «Мне нужно пояснение» или текст-просьба
  («поясни, что это») → вопрос остаётся открытым (`answered:false`, «ждёт вашего решения после
  пояснения»), руководителю уходит сигнал «пользователь просит пояснить» и требование объяснить
  в ветке. Ответить на тот же вопрос потом можно снова (раньше был `409`).
* **Шаги согласованы с ответами.** Ответ «нет / не нужно» снимает связанные шаги («снят по вашему
  ответу», в бэклоге комнаты — `dismissed`); шаг, появившийся после такого ответа, получает метку
  «противоречит вашему ответу» и кнопку «Убрать» (`action:"step_drop"`). Связь строится по
  `from_question` из metadata шага или по совпадению текста вопроса и шага.
* **API:** `OpenQuestion` дополнен `answer_state`, `answer_label`, `needs_explanation`,

## 1.0.0 — 2026-11-03

Первый публичный выпуск.

**Установка**
* одна команда PowerShell: скачивает релиз, ставит приложение и модуль «Командные
  комнаты» в Hermes Desktop, поднимает сервер и открывает страницу (`install.ps1`);
* повторная установка ничего не дублирует, `-Uninstall` убирает за собой;
* нужен только Python 3.11+ (стандартная библиотека), git не требуется;
* приложение ставится в `%LOCALAPPDATA%\\TeamRoom`, данные — в `data/` рядом.

**Комнаты и работа**
* комнаты с оркестратором и критиком, дорожная карта, бэклог с фильтрами, журнал;
* запросы: постановка, уточнения, ответ команды, согласование критиком, история;
* отчёты: блоки, таблицы, графики, график связей, выгрузка в HTML и Markdown;
* поиск по комнате и палитра команд (`Ctrl+K`);
* диктовка голосом (локальное распознавание) и словарь терминов.

**Платформа**
* сервер на стандартной библиотеке Python 3.11+, интерфейс без сборки и без CDN;
* песочница: работа с настоящей доской только на чтение, запись — в копию;
* модуль «Командные комнаты» для Hermes Desktop и сторож, который держит его живым;
* демо-стенд на выдуманных данных (`start-demo-room.cmd`).

**Переносимость**
* никаких путей автора: корень Hermes, Vault и `hermes` CLI определяются сами
  (`HERMES_HOME`, `%LOCALAPPDATA%`, `~/.hermes`, `PATH`), любую настройку можно
  переопределить переменными окружения;
* если хранилища Obsidian нет — приложение работает без зеркала и подсказывает
  `TEAMROOM_VAULT_DIR`;
* если Hermes CLI не найден — комната работает в режиме просмотра, ошибки записи
  объясняются по-русски, без трассировок;
* без `faster-whisper` диктовка сообщает «не установлено», остальное работает;
* `tools/portability_check.py` проверяет оба сценария на «чистой машине».
