# reportkit: как агенту собрать интерактивный отчёт

Этот файл — инструкция для ИИ-агента. Прочитал → сделал `report.json` → проверил `validate.py` → отдал путь.
Рендерер и стили уже написаны, тебе ничего не нужно рисовать руками.

---

## 0. Самое короткое, что нужно запомнить

```json
{
  "version": 1,
  "title": "Название отчёта",
  "subtitle": "комната Лето · 28.10.2026",
  "summary": "Один-два абзаца: главный вывод и цифры.",
  "blocks": [
    {"type": "stats", "items": [{"label": "Выручка", "value": "81 920 R$"}, {"label": "Маржа", "value": "48,8 %"}]},
    {"type": "text", "md": "**Вывод.** Что делать и почему."},
    {"type": "sources", "items": [{"title": "Калькуляция", "ref": "D:/Проекты/Vault/Projects/Лето/Финансы/смета.xlsx"}]}
  ]
}
```

Положить в `data/reports/<комната>/<slug>/report.json`, проверить:

```
python D:/Проекты/Код/reportkit/validate.py <путь>/report.json
```

Пока команда не написала `Итог: OK` — отчёт не готов.

## 1. Когда отчёт нужен, а когда нет

**Делай отчёт, если в ответе есть хотя бы одно:**

- цифры, которые надо сравнивать (цены, маржа, сроки, объёмы) — `stats`, `table`, `chart`;
- сравнение вариантов «что выбрать» — `compare`, `matrix`;
- связи и зависимости «что от чего зависит» — `graph`;
- последовательность шагов или этапов — `timeline`, `phases`, `checklist`, `kanban`;
- больше 5–6 фактов, которые иначе придётся читать простынёй;
- картинки, схемы, скриншоты — `gallery`;
- Михаил будет возвращаться к этому ответу позже.

**Не делай отчёт, если:**

- ответ укладывается в 3 абзаца и одна цифра по центру;
- это уточнение, «да/нет», «отправил», «жду ответа»;
- данных мало и они не проверены — лучше честный текст, чем красивая пустая таблица.

Правило: **отчёт — не украшение ответа, а замена простыне текста.** Если после отчёта всё равно нужен текст на две страницы — отчёт не нужен.

## 2. Куда писать файлы

Путь приходит в карточке запроса: `data/reports/<комната>/<slug>/`.

```
data/reports/cafe/r-20261028-0931-ab12/
    report.json          ← отчёт (обязательно)
    chart-1.png          ← картинки рядом, ссылайся относительно: "chart-1.png"
    смета.xlsx           ← любые файлы-приложения
```

Правила:

1. **Имя — `report.json`.** Никаких `report-v2-final.json`; перезапись — это нормально.
2. **Картинки клади в ту же папку** и указывай в `gallery` относительный путь (`"chart-1.png"`, `"assets/схема.png"`). Абсолютные пути тоже работают, если файл лежит в разрешённых корнях (`D:\Проекты`, `D:\Проекты`, `D:\Проекты`, `data/`).
3. **Файлы Vault — только абсолютными путями**: `D:/Проекты/Vault/Projects/Лето/Финансы/смета.xlsx`. Слэши прямые, буква диска обязательна.
4. **Ничего не удаляй** из папки отчёта: там могут быть файлы других шагов.
5. Путь к отчёту верни в metadata карточки: `"report": "data/reports/cafe/r-20261028-0931-ab12/report.json"`.

Картинки до 2 МБ при экспорте в HTML встраиваются внутрь файла (data: URI), больше — остаются ссылкой. Не тащи 10-мегабайтные фото.

## 3. Корень отчёта

```json
{
  "version": 1,
  "title": "Себестоимость и маржа моти",
  "subtitle": "комната Лето · 28.10.2026 · данные демо",
  "summary": "При цене 220 R$ маржа 107,43 R$ (48,8 %). Точка безубыточности — 391 шт/мес.",
  "blocks": []
}
```

| Поле | Обязательно | Что это |
|---|---|---|
| `version` | да, всегда `1` | версия формата |
| `title` | да | заголовок, до 200 символов, без точки в конце |
| `subtitle` | нет | контекст: комната, дата, «демо», период |
| `summary` | нет | 1–3 предложения с главным выводом (Markdown) |
| `blocks` | да | список блоков, от 1 до 200 (включая вложенные) |

`title` рендерер показывает крупно, `subtitle` — серым под ним, `summary` — врезкой. Если нечего сказать в summary — не пиши поле вовсе.

Лишние поля в корне и в блоках **отбрасываются** с предупреждением: рендерер их не знает. Не выдумывай свои ключи.

## 4. Блоки

Общее для всех: поле `type` обязательно, регистр не важен. Незнакомый тип — ошибка с подсказкой ближайшего.

### 4.1 `heading` — заголовок раздела

| Поле | Обяз. | Значение |
|---|---|---|
| `text` | да | до 200 символов |
| `level` | нет | `1`, `2` или `3`; по умолчанию `1` |

```json
{"type": "heading", "text": "Из чего складывается себестоимость", "level": 2}
```

`level: 1` — один раз на отчёт (обычно не нужен: `title` уже есть). Заголовки 2-го уровня попадают в оглавление слева, поэтому формулируй их как пункты меню: «Риски», «Сценарии цены», «Что делать дальше».

### 4.2 `text` — абзац с Markdown

| Поле | Обяз. | Значение |
|---|---|---|
| `md` | да | до 20 000 символов |

```json
{"type": "text", "md": "**Вывод.** Цена 220 R$ даёт 48,8 % маржи.\n\n- первый пункт\n- второй пункт"}
```

Поддерживается Markdown (см. раздел 5). Не пихай в один блок всю простыню — режь на 2–4 абзаца и заголовки.

### 4.3 `callout` — врезка-акцент

| Поле | Обяз. | Значение |
|---|---|---|
| `tone` | нет | `info` (по умолч.), `success`, `warn`, `danger` |
| `title` | нет | короткий заголовок |
| `md` | да | текст с Markdown |

```json
{"type": "callout", "tone": "warn", "title": "Где риск", "md": "Ниже 170 R$ маржинальность падает до 37 %."}
```

`danger` — только для реальной угрозы (потеря денег, срыв срока, юридический риск). Если всё хорошо — `success`. Не больше 2–3 врезок на отчёт, иначе они перестают работать.

### 4.4 `stats` — крупные цифры (KPI)

| Поле | Обяз. | Значение |
|---|---|---|
| `items` | да | 2–12 показателей (жёсткий максимум 24) |
| `items[].label` | да | подпись, до 80 символов |
| `items[].value` | да | число или строка; **единицы пиши в value или label** |
| `items[].delta` | нет | изменение: `"+12,4 %"`, `-3.1`, `"на 7 дней"` |
| `items[].hint` | нет | пояснение мелким шрифтом |
| `items[].tone` | нет | `info`, `success`, `warn`, `danger` |

```json
{"type": "stats", "items": [
  {"label": "Маржа, %", "value": "48,8", "delta": "+6,2 п.п.", "tone": "success"},
  {"label": "Безубыточность", "value": "391 шт/мес", "hint": "при 42 000 R$/мес"}
]}
```

4 штуки — идеально, 6 — предел для одной строки. Это первый блок отчёта почти всегда.

### 4.5 `table` — таблица

| Поле | Обяз. | Значение |
|---|---|---|
| `columns` | да | ≥1 колонка |
| `columns[].key` | да | латиница, уникальная, совпадает с ключами в `rows` (кириллица — предупреждение) |
| `columns[].label` | да | заголовок по-русски |
| `columns[].type` | нет | `text` (по умолч.), `number`, `money`, `percent`, `date`, `status`, `link` |
| `columns[].align` | нет | `left`, `center`, `right`; для чисел по умолчанию `right` |
| `columns[].currency` | нет | `R$` (по умолч.), `BRL`, `₽`, `$`, `€` |
| `columns[].decimals` | нет | 0–4; по умолчанию: `money` — 2, `percent` — 1, `number` — 0 |
| `rows` | да | список объектов, до 5000 строк |
| `title` | нет | заголовок таблицы |
| `sortable` | нет | клик по заголовку сортирует; по умолчанию `true` |
| `filter` | нет | поле поиска; по умолчанию включается при 25+ строках |
| `totals` | нет | `{"колонка": "sum" \| "avg" \| "count"}` |
| `footnote` | нет | сноска под таблицей |

```json
{"type": "table", "title": "Сценарии цены",
 "columns": [
   {"key": "price", "label": "Цена, R$", "type": "money", "currency": "R$", "decimals": 0},
   {"key": "margin", "label": "Маржа, R$", "type": "money"},
   {"key": "pct", "label": "Маржинальность", "type": "percent", "decimals": 1},
   {"key": "due", "label": "Срок", "type": "date"},
   {"key": "state", "label": "Статус", "type": "status"}
 ],
 "rows": [
   {"price": 190, "margin": 81.03, "pct": 42.6, "due": "2026-11-05", "state": "в работе"},
   {"price": 220, "margin": 107.43, "pct": 48.8, "due": "2026-11-20", "state": "готово"}
 ],
 "totals": {"margin": "avg"}, "footnote": "Налоги не учтены."}
```

Тонкости:

- числа — **числами** (`190`, `81.03`), не строками `"190 R$"`. Единицы и символ валюты добавит рендерер; строка сломает сортировку и итоги.
  Валидатор: нечисло в колонке `number`/`money`/`percent` — **ошибка** (`blocks[0].rows[2].price: ожидалось число`), а строка, внутри которой число (`"1 234,5"`), приводится к числу с предупреждением.
- `percent` — это уже проценты (`48.8` → «48,8 %»), не доли. Доли — `ratio: true`.
- `date` — `"2026-11-05"` или ISO с временем.
- `status` — короткая строка; цвет чипа выбирается по словам: `готово/done/ok` → зелёный, `в работе/active` → синий, `ждёт/pending` → жёлтый, `блок/отказ/ошибка` → красный. Пиши ровно одно из: `готово`, `в работе`, `ждёт`, `блок` (латинские формы `done`, `active`, `pending`, `blocked` тоже понимаются). «готов» (без «о») — не то же самое, что «готово»: цвет не определится.
- `link` — либо строка (`"D:/Проекты/Vault/.../смета.xlsx"`, `"https://…"`), либо объект `{"title": "Смета", "path": "C:/…"}`.
- `totals` — только для числовых колонок; `sum`/`avg` по тексту бессмысленны (валидатор предупредит).
- 5000 строк — предел; больше — дели на несколько таблиц по смыслу, а не по 100 строк.

### 4.6 `chart` — график

| Поле | Обяз. | Значение |
|---|---|---|
| `kind` | да | `bar`, `hbar`, `line`, `area`, `pie`, `donut`, `stacked`, `scatter` |
| `series` | да | ≥1 ряд: `{name, data, color?}` |
| `x` | да, кроме scatter | подписи по оси X (для `pie`/`donut` — названия секторов; для `stacked`/`area`/`hbar` — подписи столбцов). Без `x` — предупреждение, подписи будут `#1…#N` |
| `title` | нет | заголовок |
| `unit` | нет | `R$`, `%`, `шт` — попадает на ось |
| `note` | нет | сноска под графиком |

```json
{"type": "chart", "kind": "bar", "title": "Маржа по сценариям", "unit": "R$",
 "x": ["190 R$", "220 R$", "250 R$"],
 "series": [{"name": "Маржа", "data": [81.03, 107.43, 133.83]}]}
```

`scatter` — особый: `data` это список точек `{"x": 190, "y": 42}`, `x` не нужен.

```json
{"type": "chart", "kind": "scatter", "title": "Цена и заказы",
 "series": [{"name": "Будни", "data": [{"x": 190, "y": 42}, {"x": 220, "y": 38}]}]}
```

Когда какой:

| Хочу показать | kind |
|---|---|
| сравнить величины по категориям | `bar` (вертикально) / `hbar` (много длинных названий) |
| динамику во времени | `line` |
| динамику + объём | `area` |
| части целого (3–5) | `pie` / `donut` |
| вклад нескольких рядов в общую сумму | `stacked` |
| связь двух числовых величин | `scatter` |

Всегда: не больше 3–4 рядов на графике, `unit` заполнен, подписи `x` короткие (до 12 символов). Если значений больше 15 — покажи топ-10 и напиши в `note`, что остальное в таблице.

### 4.7 `graph` — связи и зависимости

| Поле | Обяз. | Значение |
|---|---|---|
| `nodes` | да | до 500: `{id, label, group?, note?, size?}`; без `label` подставится `id` (с предупреждением) |
| `edges` | да (может быть `[]`) | до 2000: `{from, to, label?, kind?, weight?}` |
| `layout` | нет | `layered` (по умолч.), `force`, `radial` |
| `direction` | нет | `LR` (слева направо), `TB` (сверху вниз — по умолч.) |
| `title` | нет | заголовок |

```json
{"type": "graph", "title": "Зависимости этапов", "layout": "layered", "direction": "LR",
 "nodes": [{"id": "cnpj", "label": "ИНН", "group": "база"}, {"id": "роспатент", "label": "Заявка Роспатент", "group": "бренд"}],
 "edges": [{"from": "cnpj", "to": "роспатент", "label": "заявитель"}]}
```

- `id` — латиница без пробелов, уникальный; `from`/`to` ссылаются **только** на существующие `id` (иначе ошибка).
- `label` на ребре — 1–2 слова («документы», «оплата»).
- `group` красит узлы по группам — задавай, если узлы делятся на 2–4 смысловые кучки.
- `layered` + `LR` — для процессов и зависимостей; `radial` — когда есть центр и 10–20 спутников; `force` — для «просто связанных» сущностей без иерархии.

### 4.8 `timeline` — лента событий

| Поле | Обяз. | Значение |
|---|---|---|
| `items` | да | `{date, title, md?, status?, owner?}` |
| `items[].date` | да | `"2026-11-05"` или `"ноябрь 2026"` |
| `items[].status` | нет | `done`, `active`, `next`, `blocked` |

```json
{"type": "timeline", "items": [
  {"date": "2026-11-05", "title": "Подача документов", "status": "active", "owner": "biz-lawyer", "md": "Комплект: аренда, ИНН, план."}
]}
```

Сортировка — как в JSON, рендерер не переставляет. Ставь по возрастанию даты.

### 4.9 `phases` — полоса этапов

| Поле | Обяз. | Значение |
|---|---|---|
| `items` | да | `{title, status, note?}` |
| `items[].status` | да | `done`, `active`, `next`, `blocked` |

```json
{"type": "phases", "items": [
  {"title": "Исследование", "status": "done"},
  {"title": "Экономика", "status": "active", "note": "этот отчёт"},
  {"title": "Легализация", "status": "next"}
]}
```

3–7 фаз, ровно одна `active`. Это «где мы сейчас» — ставь в начало отчёта о проекте.

### 4.10 `compare` — варианты с плюсами и минусами

| Поле | Обяз. | Значение |
|---|---|---|
| `options` | да | `{name, pros, cons, score?, verdict?}` — 2–4 варианта |
| `criteria` | нет | список критериев сравнения (строки) |
| `options[].pros/conses` | нет | списки строк, до 15 |
| `options[].score` | нет | число (например, 1–10) — рендерер покажет как оценку |
| `options[].verdict` | нет | одна фраза-вывод по варианту |

```json
{"type": "compare", "criteria": ["Стоимость", "Скорость"],
 "options": [
   {"name": "Своя кухня", "score": 7, "pros": ["Полный контроль"], "cons": ["Аренда"], "verdict": "Дорого, но правильно."},
   {"name": "Аренда по часам", "score": 9, "pros": ["Быстрый старт"], "cons": ["График"], "verdict": "Оптимум на 6 месяцев."}
 ]}
```

`verdict` обязателен по смыслу: если рекомендации нет, читатель выбирает сам и злится. 3 варианта — максимум, который ещё читается.

### 4.11 `matrix` — тепловая карта, SWOT или сетка

Три режима в одном блоке.

**heat** (риски, приоритеты) — числа, цвет по величине:

```json
{"type": "matrix", "kind": "heat",
 "rows": ["Оппозиция по классу 30", "Отказ разрешение"],
 "cols": ["Вероятность", "Влияние", "Оценка"],
 "cells": [[3, 4, 12], [2, 5, 10]]}
```

**swot** — четыре списка:

```json
{"type": "matrix", "kind": "swot", "swot": {
  "strengths": ["Узнаваемый вкус"], "weaknesses": ["Одна кухня"],
  "opportunities": ["Корпоративные заказы"], "threats": ["Рост цен на рис"]}}
```

**grid** — текст в клетках:

```json
{"type": "matrix", "kind": "grid", "rows": ["Моти"], "cols": ["Октябрь", "Ноябрь"], "cells": [["420 шт", "план 500"]]}
```

`cells[i][j]` = строка `i`, колонка `j`. Число строк в `cells` должно совпадать с `rows`, число ячеек — с `cols` (иначе предупреждение и кривая сетка). Для heat держи шкалу одинаковой во всех клетках (например, 1–5).

### 4.12 `checklist` — что сделать

| Поле | Обяз. | Значение |
|---|---|---|
| `items` | да | `{text, done?, owner?, due?}` |
| `items[].done` | нет | `true`/`false`; строка `"done"`, `"да"`, `"готово"` тоже понимается |

```json
{"type": "checklist", "items": [
  {"text": "Согласовать цену 220 R$", "done": true, "owner": "Михаил"},
  {"text": "Запросить КП на муку", "done": false, "owner": "biz-ops", "due": "2026-11-05"}
]}
```

`due` — ISO-дата. Владелец — профиль агента или имя человека.

### 4.13 `kanban` — мини-доска

```json
{"type": "kanban", "lanes": [
  {"title": "Надо", "cards": [{"title": "Вторая кухня", "note": "в радиусе 3 км", "tag": "операции"}]},
  {"title": "В работе", "cards": [{"title": "Юнит-экономика", "tag": "финансы"}]},
  {"title": "Готово", "cards": [{"title": "Меню из 5 вкусов"}]}
]}
```

3–4 колонки, 2–5 карточек в каждой. `tag` — одно слово-категория.

### 4.14 `gallery` — картинки

```json
{"type": "gallery", "images": [{"src": "chart-1.png", "caption": "Выручка по неделям"}]}
```

`src` — относительный путь от папки отчёта (или абсолютный в разрешённых корнях). Форматы: png, jpg, gif, webp, svg. `caption` — что на картинке, не «рисунок 1».

### 4.15 `code` — код или сырой текст

```json
{"type": "code", "lang": "json", "text": "{\"key\": \"value\"}"}
```

`lang` — подпись в углу (`json`, `python`, `bash`, `diff`). Подсветки нет. Для длинных логов — не больше 200 строк, остальное в файл и `links`.

### 4.16 `tabs` — вкладки

```json
{"type": "tabs", "tabs": [
  {"title": "ИП", "blocks": [{"type": "text", "md": "Кому подходит: один собственник."}]},
  {"title": "LTDA", "blocks": [{"type": "text", "md": "Кому: два и более собственника."}]}
]}
```

Внутри `blocks` — любые блоки, включая `columns`, `table`, `accordion`. Вкладки хороши, когда вариантов 2–4 и читателю нужен один. Не прячь в них главный вывод — его не видно, пока не кликнешь.

### 4.17 `accordion` — раскрывающиеся секции

```json
{"type": "accordion", "items": [
  {"title": "Почему три уровня вложенности — максимум?", "open": true,
   "blocks": [{"type": "text", "md": "Глубже — читатель теряет контекст."}]}
]}
```

`open: true` — раскрыть сразу (один такой на аккордеон). Для FAQ, деталей и «а если».

### 4.18 `columns` — колонки

```json
{"type": "columns", "widths": [2, 1], "cols": [
  [{"type": "text", "md": "**Левая, шире.** Пояснение и цифры."}],
  [{"type": "callout", "tone": "warn", "md": "Правая, уже — ремарка."}]
]}
```

`cols` — список списков блоков. `widths` — относительные веса (по умолчанию равные). На узком экране колонки схлопываются в столбик. 2 колонки — норма, 3 — уже тесно.

### 4.19 `links` — ссылки на файлы и адреса

```json
{"type": "links", "items": [
  {"title": "Смета проекта", "path": "D:/Проекты/Vault/Projects/Лето/Финансы/смета.xlsx", "note": "лист «моти»"},
  {"title": "Документация Роспатент", "url": "https://www.Госуслуги/роспатент"}
]}
```

Нужен `path` **или** `url`. `path` — файл из белого списка (Vault, проект, data), `url` — внешний адрес (откроется в браузере; в автономном HTML офлайн не откроется).

### 4.20 `sources` — источники

```json
{"type": "sources", "items": [
  {"title": "Калькуляция себестоимости", "ref": "D:/Проекты/Vault/Projects/Лето/Финансы/смета.xlsx", "note": "лист «моти», ред. 12.10"},
  {"title": "Роспатент, руководство по знакам", "ref": "D:/Проекты/Vault/Projects/Лето/Право/Роспатент.md"}
]}
```

Обязателен, если в отчёте есть цифры, даты, сроки или юридические утверждения. `ref` — путь к файлу или название документа; не выдумывай реквизиты.

## 5. Markdown внутри `text`, `callout`, `summary`, `timeline.md`

Поддерживается (и только это):

| Синтаксис | Результат |
|---|---|
| `**жирный**`, `*курсив*`, `~~зачёркнутый~~` | акценты |
| `` `код` `` и ```` ```блок``` ```` | моноширинный текст |
| `- пункт` / `1. пункт`, вложенность пробелами | списки |
| `> цитата` | цитата |
| `# … ####` | заголовки внутри текста |
| `\| a \| b \|` + `\|---\|---\|` | таблица |
| `[текст](https://…)`, `[текст](C:/путь/файл.md)` | ссылка |
| `---` | разделитель |
| `![alt](путь)` | картинка |

Чего **нельзя**: сырой HTML (`<b>`, `<script>`) — он экранируется и покажется текстом; `javascript:`-ссылки вырезаются. Не пытайся верстать отступами и пробелами — используй блоки.

Один абзац = пустая строка между абзацами. Одиночный перенос строки остаётся внутри абзаца.

## 6. Рецепт хорошего отчёта

Порядок блоков, который работает почти всегда:

```
stats         ← 3–4 главные цифры (или callout с выводом, если цифр нет)
text          ← «Вывод»: 2–3 предложения, что это значит
heading 2     ← дальше — детали
table/chart   ← данные
callout warn  ← где риск / чего не учесть
heading 2
...           ← остальные детали
checklist     ← что делать (если есть действия)
sources       ← в самом конце
```

Правила:

1. **Один экран до сути.** Первые 2 блока должны отвечать на вопрос «ну и что?». Если человеку надо скроллить, чтобы понять вывод, — переделай.
2. **Русский язык.** Заголовки, подписи, статусы — по-русски. Латиница — только в `id`, `key`, `lang` и путях.
3. **Числа с единицами.** «391 шт/мес», «48,8 %», «86,17 R$». Не «391» и не «0.488».
4. **Один отчёт — один вопрос.** Не сваливай юнит-экономику, юридику и маркетинг в один файл: будет 60 блоков и никто не дочитает.
5. **Не больше 40–50 блоков.** Лимит 200 — технический, читательский предел ниже.
6. **Заголовки — как пункты меню**: «Риски», «Сценарии цены», а не «Раздел 3».
7. **Врезок мало.** `danger` — реально опасное. Если всё «важно», не важно ничего.
8. **Источники в конце** и только те, что реально использовал.

## 7. Как проверить (обязательный шаг)

```bash
python D:/Проекты/Код/reportkit/validate.py <путь>/report.json
```

Что печатает:

```
Отчёт: «Себестоимость и маржа моти» — unit-economics.report.json
Блоков: 12 (лимит 200), строк таблиц: 10 (лимит 5000), узлов графов: 0 (лимит 500)

ОШИБКИ (1) — отчёт не будет показан:
  1. blocks[3].series[0].data: ожидалось число, получено строка

ПРЕДУПРЕЖДЕНИЯ (1) — исправлено автоматически:
  - blocks[0].level: число задано строкой ('2') — приведено к целому

Итог: ЕСТЬ ОШИБКИ. Исправьте их и запустите проверку снова.
```

- **Код возврата 0** — отчёт корректен, можно отдавать. **1** — есть ошибки.
- Каждая ошибка начинается с **адреса поля**: `blocks[3].series[0].data` = четвёртый блок, первый ряд, поле `data`. Иди ровно туда.
- **Ошибки** — отчёт не покажется вообще (или покажется с дырками). Исправлять обязательно.
- **Предупреждения** — валюту/строки/длину уже поправили за тебя; показ не ломается. Прочитай их: там бывает важное («колонки X нет», «картинка не найдена»).

Полезные флаги:

```bash
python validate.py report.json --quiet          # только ошибки
python validate.py report.json --json           # машиночитаемый результат
python validate.py report.json --write fixed.json  # сохранить нормализованную версию
```

Нормализация (делается сама, с предупреждением): `"level": "2"` → `2`; `"done": "done"` → `true`; `kpi` → `stats`; `text` у callout → `md`; числа строкой → числа; слишком длинный текст → обрезка. Если видишь предупреждение — лучше исправь исходник, а не полагайся на нормализацию.

Ещё одна проверка — глазами:

```bash
python D:/Проекты/Код/reportkit/export_html.py <путь>/report.json <TEMP>/check.html
```

Открой файл в браузере: так ты увидишь ровно то, что увидит Михаил (и заметишь пустые графики, кривые подписи, гигантскую таблицу).

## 8. Свободный `report.html` — когда можно

Иногда нужен не набор блоков, а своя страница (нестандартная визуализация, интерактив, канвас). Тогда вместо `report.json` положи `report.html`.

Можно, если:

- блоков не хватает по смыслу (своя диаграмма Ганта, кастомный калькулятор, анимация);
- это разовый эксперимент, а не типовой отчёт;
- HTML **один файл**: стили и скрипты внутри, без внешних `<script src>`, `<link href>`, шрифтов и CDN.

Нельзя:

- сеть (никаких `http://` в `src`/`href`/`fetch`/`import`), внешних шрифтов и картинок по URL;
- обращаться к `parent`, `top`, `window.parent` — страница живёт в песочнице;
- `document.cookie`, `localStorage` (в песочнице недоступны), формы с отправкой куда-либо;
- секреты, токены, пароли в коде страницы.

Как показывается: `<iframe sandbox="allow-scripts">` с CSP `default-src 'none'; img-src 'self' data:; style-src 'unsafe-inline'; script-src 'unsafe-inline'`. То есть инлайн-скрипты работают, а всё внешнее — нет.

В metadata карточки укажи `"report": "data/reports/<комната>/<slug>/report.html"`. Если сомневаешься — делай JSON: он безопаснее, единообразнее и его можно экспортировать в автономный HTML.

## 9. Типичные ошибки

| Симптом в валидаторе | Причина | Как исправить |
|---|---|---|
| `неизвестный тип блока 'tabls'` | опечатка в `type` | взять тип из списка (подсказка в тексте ошибки) |
| `blocks[2].items: обязательное поле отсутствует` | у `stats` нет `items` | `{"type":"stats","items":[...]}`, не `{"type":"stats","values":[...]}` |
| `blocks[1].md: обязательное поле отсутствует` | текст положили в `text`/`content` | у `text` и `callout` поле называется `md` |
| `blocks[4].series[0].data: ожидалось число` | в данных `"81,03 R$"` | числа числами: `81.03`, единицы — в `unit` |
| `blocks[0].nodes[3].id: id 'a' уже занят` | дубли `id` | уникальные латинские id |
| `blocks[0].edges[0].from: узла 'x' нет в nodes` | ребро ссылается на несуществующий узел | добавить узел или исправить `id` |
| `blocks[6].columns[0].key: пустая строка` | колонка без `key` | `key` — латиница, совпадает с ключами `rows` |
| `блоков больше лимита 200` | отчёт-монстр | разбить на 2–3 отчёта по вопросам |
| `слишком глубокая вложенность (уровень 4)` | `tabs` внутри `tabs` внутри `tabs` | максимум 3 уровня, лучше 2 |
| `таблица: строк 6000 — больше лимита` | вся выгрузка в одну таблицу | топ-50 + файл в `links` |
| предупреждение `нет значений для колонок: x` | в `rows` нет ключа из `columns` | добавить значение или убрать колонку |
| предупреждение `поле не используется` | придуманное поле (`"color"` у `text`) | убрать; смотреть таблицу полей выше |
| `Итог: OK`, но в браузере пусто | блок с неверной структурой данных | открыть `export_html.py` и посмотреть глазами |

Ещё три немых убийцы:

1. **BOM и `\r\n`** — не проблема, читаем `utf-8-sig`.
2. **Запятая как десятичный разделитель в JSON** — невалидный JSON. В JSON только точка: `81.03`.
3. **Висячая запятая** перед `}` — невалидный JSON. Валидатор скажет «некорректный JSON — строка N».

## 10. Лимиты (сводка)

| Что | Предел | Что будет при превышении |
|---|---|---|
| Блоков всего (с вложенными) | 200 | ошибка |
| Блоков в отчёте | ≥ 1 | `blocks: []` — ошибка (`показывать нечего`) |
| Глубина `tabs`/`accordion`/`columns` | 3 | ошибка |
| Строк в таблице | 5000 | ошибка, обрезка |
| Узлов графа | 500 | ошибка |
| Связей графа | 2000 | ошибка |
| `stats.items` | 12 рекомендуемо, 24 максимум | предупреждение / ошибка |
| Текст одного `md` | 20 000 символов | обрезка + предупреждение |
| `title` / подпись | 200 символов | обрезка |
| Значение в `stats.value` | 60 символов | обрезка |
| Ячейка таблицы | 400 символов | обрезка |
| Картинка для встраивания в HTML | 2 МБ | останется ссылкой + предупреждение |

## 11. Чек-лист перед сдачей

- [ ] Блоков ≥ 1: пустой `blocks` — ошибка, а не «OK с предупреждением».
- [ ] Первые два блока отвечают «ну и что?».
- [ ] Числа — числами, единицы — в подписях; итоги сходятся с таблицей.
- [ ] Все цифры и утверждения есть в `sources`.
- [ ] Нет латиницы в видимых подписях (кроме единиц и названий).
- [ ] Нет выдуманных путей к файлам: если файла нет — не ссылайся.
- [ ] Отчёт открыт глазами через `export_html.py` (хотя бы раз).
- [ ] Путь к отчёту указан в metadata карточки (`report`).
