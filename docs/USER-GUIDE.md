# «Комната команды» — руководство

Это приложение для одного человека: вы пишете **один** главный запрос — получаете **один** связный ответ. Исполнителей выбирать не нужно: руководитель комнаты сам раскладывает работу по участникам, критик (если включён) проверяет свод, а приложение складывает всё накопленное в одно место — направления, этапы, решения, следующие шаги, журнал, папку проекта и заметки в Obsidian.

Всё работает на вашем компьютере: приложение отвечает только по адресу `127.0.0.1`, в интернет ничего не уходит, аккаунтов и подписок не нужно.

В тексте кнопки и вкладки названы так же, как на экране. Пути записаны общепринято: `<папка приложения>` — куда вы распаковали программу, `%LOCALAPPDATA%\hermes` — папка данных Hermes (если задана переменная `HERMES_HOME`, путь берётся из неё).

## 1. За пять минут

1. Запустите `<папка приложения>\start-team-room.cmd` (двойной щелчок). Откроется окно с сервером и браузер на `http://127.0.0.1:8777`. Окно сервера закрывать нельзя — это и есть приложение.
2. Слева выберите комнату. Комнат может быть несколько — по одной на проект.
3. Вкладка **«Запрос»** → большое поле. Надиктуйте или напишите текст.
4. **«Отправить»** (или `Ctrl+Enter`). Откроется страница запроса.
5. Смотрите на статус вверху. Когда появится ответ — он будет первым блоком страницы.

Если у комнаты включён **проектный режим** (так у новых комнат по умолчанию), первый запрос работает как бриф: руководитель не бросается исследовать, а сначала предлагает **карту направлений**. Вы смотрите карту и нажимаете **«Запустить»**. Подробно — раздел 4.

Семь статусов запроса, которые полезно узнавать с первого взгляда:

| Чип | Что значит | Что делать |
|---|---|---|
| в очереди | запрос принят, разбор ещё не начался | подождать; если долго — «Разложить сейчас» |
| в работе | команда работает | ждать, можно смотреть «Дерево работ» |
| проверка | критик читает свод | ждать |
| сводит | руководитель пишет новую версию ответа | ждать |
| готово | ответ есть | читать «Ответ», потом «Дальше» |
| нужен ответ | команда ждёт вас | «Дальше» → ответить в строке |
| ошибка | работа сорвалась | открыть запрос, посмотреть дерево и «Хронологию» |

Три правила, которые сэкономят время:

- **Один запрос — один ответ.** Не нужно писать «сделай то, потом это» пятью сообщениями: команда сама разложит.
- **Ничего не теряется.** Шаги и вопросы оседают в «Дальше», решения — в «Карте проекта», файлы — в папке проекта, заметки — в Obsidian.
- **Всё локально.** Никакой отправки наружу.

## 2. Диктовка: говорите, а не печатайте

### Где диктовка

Микрофон есть **везде, где есть поле для текста**: в запросе, в сообщении руководителю, в ответе на вопрос, в названии комнаты, в папке проекта, в особых указаниях, в правке направления. Включать ничего не нужно — кнопка с микрофоном появляется рядом с полем сама.

- Кнопка называется **«Надиктовать»** (если у поля мало места — просто значок микрофона).
- Нажмите и говорите: текст встанет туда, где стоит курсор. Поле не блокируется — можно печатать и править на ходу.
- Остановить — та же кнопка (**«Стоп»**) или `Ctrl+M`.
- Пока идёт расшифровка, кнопка показывает **«Расшифровываю…»**. Первый запуск после включения компьютера занимает до минуты: загружается модель распознавания. Дальше — доли секунды.
- Если запись не отправилась, текст не пропадает: останется кнопка **«Распознать ещё раз»** — запись сохранена.

### Десять минут на одну запись — и ничего не теряется

Одна запись — **до 10 минут**. Лимит берётся из настроек Hermes (в панели видно «0:07 / 10:00», а если там 15 минут — будет 15). За 30 секунд до конца приложение предупредит: «Осталось меньше 30 секунд — запись сама уйдёт на распознавание».

Длинная запись режется на части по две минуты. Каждая часть сразу сохраняется на диск (и в браузере) и распознаётся — поэтому **любой сбой переживает запись**:

- Дошли до лимита — запись останавливается сама и уходит на распознавание, ничего нажимать не нужно.
- Пропала сеть, сервер занят — уже распознанное вставится, а рядом с полем появится «Распознать ещё раз».
- Закрылось окно модуля или страница перезагрузилась — части остались на диске. Откройте микрофон в нужном поле: в панели будет «**Есть нерасшифрованная запись · 6:12**» и кнопка **«Распознать запись»**. Текст встанет в поле.
- Пока части распознаются, рядом с полем видно «Распознано 3 из 7 минут», а поле остаётся свободным — можно печатать.

Удалить наговоренное можно только самому: `Esc` или «Отмена». Сами записи убираются через три дня (не больше 30 штук).

### Словарь: имена и термины

Распознавание не обучается само, но ему можно **заранее подсказать слова**: названия фирм, имена, термины, аббревиатуры. Тогда они распознаются правильно с первого раза.

**Настройки → «Диктовка и словарь»**:

| Что там | Зачем |
|---|---|
| **Слова и имена** | список слов, которые надо узнавать. Добавили один раз — работает во всех полях |
| **Автозамены** | пары «как распознал → как должно быть». Срабатывают после распознавания, до того как текст попал в поле |
| **Проверить на фразе** | вставьте фразу с ошибками — увидите, какой она станет. Ничего никуда не отправляется |
| **Файл словаря** | сохранить словарь одним файлом (перенести на другой компьютер) или загрузить готовый |

У заголовка — счётчик слов. Слов может быть много, но каждая автозамена должна быть короткой и однозначной: «тескфло → TaskFlow» полезно, «всё → ничего» — нет.

### «Запомнить исправление?»

Самое удобное место. Вы надиктовали текст, поправили в нём пару слов руками и отправили. Приложение сравнивает, что было распознано и что вы отправили, и предлагает:

> **Запомнить исправление?** «тескфло» → «TaskFlow»

- **«Запомнить»** — в следующий раз исправит само. Приложение подтвердит: «Запомнил. В следующий раз исправлю сам».
- Если правок несколько — отметьте галочками нужные и нажмите **«Запомнить выбранные»** (или **«Запомнить все»**).
- **«Скрыть предложение»** — если это была разовая опечатка, а не привычка распознавания.

Сравниваются только слова: пунктуация и заглавные буквы в счёт не идут, поэтому случайно исправленная запятая не превратится в правило.

### Если микрофон не отвечает

Приложение скажет, что случилось, человеческим языком:

| Сообщение | Что сделать |
|---|---|
| «Разрешите микрофон…» | значок замка рядом с адресом → Микрофон → Разрешить; обновите страницу |
| «Микрофон не найден» | подключите микрофон (наушники, гарнитуру) и попробуйте снова |
| «Микрофон занят другой программой» | закройте программу, которая пишет звук (звонок, диктофон) |
| «Распознавание речи не готово — сервер ещё запускается» | подождите минуту: первый раз модель грузится |
| «Речь не обнаружена» | говорите ближе к микрофону; тишина — не ошибка, просто нечего расшифровывать |

Пока микрофон не отвечает, поле работает как обычно — можно печатать.

## 3. Комната: как её завести

Комната — рабочий стол под один проект: свой руководитель, свой состав, своя карта, своя папка. Кнопка **«+»** у списка комнат (или Настройки → «Новая комната») открывает диалог.

| Поле | Что это | Подсказка |
|---|---|---|
| **Название** | 2–80 знаков | коротко: проект или направление |
| **Иконка** | значок в списке слева | на вкус |
| **Руководитель комнаты** | участник, который раздаёт работу и сводит ответ | без него комнату не создать: он держит всё вместе |
| **Критик комнаты** | кто проверяет свод перед ответом | можно «Без критика»; критик и руководитель — разные участники |
| **Раунды проверки** | сколько раз критик проверяет свод: «1 раунд — быстро», «2 раунда — тщательнее», «До полного одобрения критиком» | «раунд» — один цикл «критик проверил → доработали → проверили снова». Кнопка «?» рядом объясняет это же; для режима «до одобрения» есть страховочный потолок раундов |
| **Состав** | кого руководитель может звать в работу | отметьте галочками; хотя бы один |
| **Особые указания участникам** | добавка к роли — только для этой комнаты | см. ниже |
| **Папка проекта** | куда команда складывает файлы | можно оставить пустым и задать позже |
| **Проектный режим** | работать через карту направлений | у новых комнат включён |
| **Как запускать направления** | «Сначала план» (ждут кнопки «Запустить») или «Сразу» | рекомендуем «Сначала план» |
| **Одновременно направлений** | 1–4 | больше — быстрее, но быстрее расходуется лимит модели |
| **Файлы контекста** | что агенты читают первыми (STATE.md, брифы, договоры) | необязательно |

**Руководитель и критик** входят в комнату отдельно, в составе их отмечать не нужно. Если профиля руководителя нет на диске, комната создастся, но работать будет некому — выбирайте из списка, который показывает приложение.

### Папка проекта

Это одно место, где лежат **результаты** работы: отчёты, таблицы, документы, черновики. Чтобы не искать по всему компьютеру.

- В поле **«Папка проекта»** можно надиктовать путь, а можно нажать **«Предложить»** — приложение подставит разумный путь по названию комнаты.
- Пока вы печатаете, приложение проверяет адрес и говорит словами: папки ещё нет (создадим при сохранении), папка есть, писать нельзя. Служебные и системные папки не принимаются — это защита от «сохраню в Windows».
- Папка создаётся при сохранении комнаты.
- Внутри — по подпапке на запрос: `<папка проекта>\<дата> <название запроса>\`. Плюс файл `README.md` — автоматическое «содержание»: какие папки есть и сколько в них файлов.
- Кнопка **«Открыть папку проекта»** — на вкладках комнаты и на странице запроса. Если папка не задана, вместо кнопки тихая подсказка: «Задайте папку проекта, чтобы результаты работы собирались в одном месте».

Правило, которое команда получает в каждой задаче: итоговые файлы — в папку проекта, в подпапку этого запроса; краткое содержание — в заметку Obsidian. Исключение — только если вы сами написали другое место.

### Особенности для этой комнаты

У каждого отмеченного участника (и у руководителя, и у критика) есть блок **«Особенности для этой комнаты»** — на карточке в «Команде» и в окне «Изменить». Это добавка к его роли, которая действует **только здесь**:

- «Отвечай коротко и только цифрами».
- «Всегда проверяй по закону X».
- «Ornith слабая модель, но локальная — простые задачи поручать ей».

Как это устроено:

- Это **список записей**, а не один текст: у каждой записи видно, кто её добавил (вы или руководитель комнаты), откуда она (задача, ваш комментарий), когда и сколько раз пригодилась.
- Поле «Добавить» с микрофоном, рядом счётчик «записей N из 24 · M из 8000 знаков». Запись сохраняется сразу — кнопка «Добавить».
- **Ваши записи закреплены** (синяя полоска). Руководитель комнаты их не удаляет; убрать может только вы — крестиком у записи.
- **Руководитель комнаты пополняет записи сам**, по итогам работы и по вашим комментариям («Ornith слабая — простое поручать ей»), в том числе себе. Спрашивать разрешения он не будет: не понравилось — поправьте.
- **Рост ограничен:** 24 записи и 8 000 знаков на участника. После каждых 5 записей и при переполнении идёт переоценка: дубли сливаются, устаревшее и ни разу не использованное убирается. Кнопка «Сократить» показывает, что именно уйдёт, и только потом убирает.
- **Журнал:** кнопка «Журнал» у участника — кто, что, зачем и по какому источнику изменил; у каждого изменения есть «Откатить».
- Указания доходят до агента двумя путями: в начало его задачи и отдельной заметкой в его рабочей карточке. Если записи поменялись, в карточку придёт обновление.
- Приоритет: сначала роль участника, потом указания комнаты, потом текст запроса. В самом запросе можно прямо переопределить указание комнаты.
- Собственные настройки участника (SOUL.md) не меняются — вы не переписываете его характер, только уточняете работу в этой комнате.
- Если в тексте окажется что-то похожее на пароль или ключ, приложение предупредит (но не заблокирует), а в карточках и Obsidian такое маскируется.

Вкладка **«Команда»**: у каждой карточки — раскрытие «Особенности для этой комнаты» с числом записей; в «Как работает комната» — сводная строка «Особые указания» (кто и что написал).

### Подписи участников: кто это и чем занимается

На каждой карточке в «Команде» заголовок — **имя и должность** из описания профиля Hermes:
«Анна — финансы и экономика (CFO)». Под ним мелко стоит техническое имя профиля (`biz-cfo`),
рядом — роль в комнате бейджем («исполнитель», «критик комнаты»). Описание профиля —
одна короткая строка, полный текст открывается кнопкой «ещё».

- Та же подпись — везде: при создании комнаты в списке состава, в чипах участников на странице
  запроса, в дереве работ, у адресатов вопросов, на карте проекта и в шапке комнаты.
- Если у профиля описания нет (например `default`), карточка называется по роли в комнате
  («Руководитель комнаты»).
- Свою подпись можно задать руками: кнопка **«Подпись»** на карточке участника. Она действует
  только в этой комнате; пустое поле — вернуть подпись из описания профиля. Файлы профиля
  (SOUL.md, config.yaml) при этом не меняются.

### Проектный режим

Три настройки определяют, как комната работает:

1. **Проектный режим** — включён: у комнаты появляется карта направлений, а первый запрос работает как бриф. Выключен: комната работает по-старому, каждый запрос — отдельная работа команды.
2. **Как запускать направления** — «Сначала план»: руководитель предлагает карту, работа начинается только после вашего «Запустить». «Сразу»: предложенные направления идут в работу без подтверждения.
3. **Одновременно направлений** — 1–4. Остальные ждут в очереди и соблюдают порядок («после …»).

Менять можно в любой момент: откройте комнату → «Изменить». Проектный режим можно выключить и включить позже — карта при выключении не пропадает, просто перестаёт показываться.

## 4. Главный запрос: бриф → карта → «Запустить»

Главный сценарий проекта. Четыре шага и одно нажатие.

### Шаг 1. Бриф

В комнате с проектным режимом у поля запроса появляется галочка **«Это бриф проекта»**. В пустой комнате первый запрос считается брифом сам — галочка уже стоит.

Бриф — это не «сделай всю работу», а «вот что мне нужно, разложи». Руководитель в ответ:

- пишет, как понял задачу;
- задаёт 0–5 вопросов, без которых нельзя начать (у каждого — вариант ответа по умолчанию);
- предлагает **карту**: 3–8 направлений.

Галочка запоминается вместе с черновиком: включать её каждый раз не нужно.

### Шаг 2. Смотрите карту

Ответ на бриф — обычный ответ плюс блок **«Предложенная карта»**. Туда же ведёт вкладка **«Карта проекта»** → блок **«Направления»**.

Что видно у каждого направления:

- название и цель одной строкой;
- ответственный и участники;
- срок;
- статус: **Предложено · В очереди · Идёт · Ждёт лимит · На проверке · Готово · Отложено**;
- от кого пришло: «предложил руководитель» или «добавил вы»;
- зависимость — «после «Исследование рынка»»;
- ссылка на под-запрос, когда направление уже запущено.

Кнопки: **«Запустить всё»**, **«Запустить»** у направления, **«Отложить»**, **«Изменить»**, **«Добавить направление»**, **«Собрать карту из запросов комнаты»** (руководитель посмотрит, что уже сделано, и пересоберёт карту).

Пустое состояние говорит прямо: «Карты пока нет. Напишите главный запрос — руководитель комнаты предложит направления».

### Шаг 3. «Запустить»

Перед запуском приложение показывает, что произойдёт: сколько направлений, «до N агентов одновременно», как ведёт себя лимит модели. Без технических слов и без сюрпризов.

После подтверждения каждое направление становится **отдельным запросом комнаты** — со своим ответом, шагами и диалогом. Дробить руками ничего не нужно.

### Шаг 4. Направления идут по очереди

- Сначала запускаются те, у которых нет зависимостей. Остальные ждут — со статусом «В очереди» и подписью «после «…»».
- Одновременно работает столько направлений, сколько вы разрешили (1–4). Остальные ждут: так не сгорает лимит модели.
- Когда направление готово, следующее стартует само.
- Ускорить — настройки комнаты → «Одновременно направлений». Притормозить — «Отложить» у направления.
- Упёрлось в лимит модели — статус **«Ждёт лимит»**, и оно продолжится само, когда лимит снимется. Перезапускать не надо.

### Как изменить карту голосом

Карту правит руководитель — вам достаточно сказать словами. Три способа:

1. **Сообщением в запрос.** Откройте бриф, в блоке «Диалог по запросу» надиктуйте: «Третье направление не нужно, а проверку документов поставь после расчёта, срок — до 20 ноября». Отправьте — сообщение уйдёт руководителю. Он поправит карту, а в «Журнале» будет видно, что и почему изменилось.
2. **Кнопкой «Изменить»** у направления — если проще руками: название, цель, ответственный, участники, срок.
3. **«Добавить направление»** — новое направление, которое придумали вы.

Что применяется сразу, а что ждёт вашего слова (сделано специально, чтобы карта не «поехала» без вас):

| Правка | Когда применяется |
|---|---|
| срок, ответственный, участники, название, цель, отложить | сразу |
| новое направление | появляется как «Предложено» — нужно «Запустить» |
| вернуть отложенное в работу | тоже через «Запустить» |

Любая правка попадает в **«Журнал»** одной строкой по-русски: кто, что и почему.

## 5. Что относится к запросу, а что ко всей комнате

Раньше это было неочевидно. Теперь подписано на экране.

- Вкладки комнаты («Запрос», «Команда», «Карта проекта», «Дальше», «Отчёты», «Журнал») — это **вся комната**. В шапке рядом с ними стоит бейдж **«вся комната»**.
- Страница запроса — это **один запрос**. Вверху крошки: `Комната «Пример-комната» › Запрос «…»`. Правая колонка подписана **«По этому запросу»**, рядом ссылка **«Все дела комнаты →»**.
- Если вы пришли на вкладку «Дальше», «Отчёты» или «Журнал» со страницы запроса, сверху появляется чип **«Только этот запрос»** — видно только то, что относится к нему. Крестик на чипе снимает фильтр.
- В «Дальше» есть переключатель **«Все · Только этот запрос»**; в блоке «Ждут вашего решения» у каждой строки написано, из какого она запроса (ссылка).
- У под-запроса направления крошки длиннее: `Комната › Бриф › Направление` — сразу понятно, откуда он взялся.

Простое правило: **крошки и бейдж отвечают на вопрос «где я» быстрее, чем название вкладки**.

## 6. Страница запроса

Открывается по щелчку на запрос (или сразу после отправки).

Сверху: заголовок, статус, предупреждения (если есть), **«Ход работы»** — полоса этапов «Разбор → Работа → Критик → Сводка → Готово» с прогрессом `N / M`, затем **«Ответ»** — крупный текст, один связный ответ по-русски. Если версий несколько, показывается последняя; рядом переключатель версий, а на старой — предупреждение «Показана версия N из M: это не последний ответ» и ссылка «К актуальной».

Ниже и справа:

- **«Диалог по запросу»** — см. 6.1.
- **«Проверка критика»** — если запрос шёл с критиком: вердикт, раунд (в режиме «до полного одобрения» — «раунд N · до полного одобрения (потолок 12)»), ход цикла «замечаний было K, закрыто M, осталось R», замечания «где · в чём проблема · что исправить», кнопка «Запустить критика». Если цикл остановлен страховкой (замечания повторяются или достигнут потолок) — заметная плашка с причиной и кнопкой «Продолжить проверку»; если у провайдера кончился лимит — плашка «цикл на паузе, продолжится сам».
- **«Дальше»** — шаги, вопросы, решения (раздел 7).
- **Встроенный отчёт** — таблицы, графики, связи; открывается на весь экран.
- **«Дерево работ»** — карточки-подзадачи: исполнитель, статус, время, итог. У каждой «Повторить», «Переназначить», «На доработку».
- **«Артефакты»** — файлы, созданные по ходу: открыть, скопировать путь, показать в проводнике. Путь внутри папки проекта показывается относительно неё — короче и понятнее.
- **«Хронология»** — что происходило по этому запросу.

Под ответом: **«На доработку…»**, **«Копировать»**, **«Скачать .md»**. В меню страницы: клонировать, подтолкнуть движок, разложить сейчас (только для «в очереди»), экспорт `.md` / `.html`, печать, архив. Недоступные по статусу пункты не прячутся молча — подсказка говорит, когда станут доступны.

### 6.0 Вопросы справа: «Вопрос — ваш ответ» и что с ним стало

Колонка справа на странице запроса — про вас: вопросы руководителя, ваши ответы и реакция
на них. Вопросы стоят первыми, под ними — план руководителя.

- Колонка шире и растёт вместе с окном (на широком экране — до 460 px). С 900 px и уже
  вопросы уходят под основной блок: горизонтальной прокрутки нет.
- **Ответ стоит рядом со своим вопросом**, а не россыпью в общем чате: блок «Вопрос — ваш ответ»
  прямо под вопросом. В диалоге по запросу ответ тоже помечен как «ответ на вопрос»
  (с цитатой вопроса и кнопкой «К вопросу»).
- **Виден статус ответа:** «ответ отправлен — руководитель ещё не ответил» → «принято
  руководителем» → «учтено: работа пересмотрена» / «принято: менять ничего не нужно».
  Под ответом — короткая **реакция руководителя** («Принято: …») и карточки, которых она коснулась.
  Если ответ изменил уже сделанное, это сказано отдельной строкой.
- **Нет реакции** — честная подпись «руководитель ещё не ответил» и кнопка
  **«Напомнить руководителю»** (одно короткое напоминание; после отправки видно, когда).
- **Поле ответа как в composer:** «Ваш ответ…» + отдельные кнопки **«Надиктовать»** (микрофон
  встаёт рядом с полем) и **«Отправить»** (`Ctrl+Enter`). Нужно уточнить сам вопрос —
  кнопка **«Мне нужно пояснение»**: вопрос остаётся открытым, пока руководитель не пояснит.
- **Окно диктовки не прыгает:** оно всегда у своего вопроса — при записи, при «Стоп»,
  при распознавании, при прокрутке и при обновлении страницы.

### 6.1 Диалог по запросу: сообщение уходит руководителю

Место, где вы уточняете задачу, пока команда работает, или задаёте вопрос после ответа.

- Лента: вы — справа и выделены; команда — слева, с ролью и аватаром; служебные события — тонкой серой строкой.
- Поле ввода с микрофоном и скрепкой (прикрепить файл по пути; файл не копируется).
- Кнопка **«Отправить руководителю»** (или `Ctrl+Enter`). Подсказка под полем говорит главное: «Сообщение получит руководитель комнаты, он передаст нужным участникам».
- Галочка **«Срочно: пересмотреть план целиком»** — если менять нужно не мелочь, а весь ход работы. Начатую работу при этом никто не останавливает.

Куда уходит сообщение: руководитель получает его первым и решает, кого это касается. Он передаёт нужным участникам, при необходимости переставляет работы и отвечает вам в диалоге («Принял; передал: …»). Остальных не трогает — работа не встаёт из-за одного уточнения.

Если новое сообщение пришло, пока предыдущее ещё не взято в работу, оно допишется к той же задаче — руководитель не получит два одинаковых письма.

Кнопка меняется по состоянию:

| Состояние запроса | Вторая кнопка | Что делает |
|---|---|---|
| идёт работа | — | уточнение по ходу, только «Отправить руководителю» |
| готово | **«Отправить на доработку»** | руководитель собирает новую версию с вашим текстом |
| ошибка | **«Повторить с уточнением»** | повтор с вашим пояснением |

Пустое состояние подсказывает: «Здесь можно уточнить задачу, пока команда работает, или задать вопрос после ответа».

## 7. «Дальше»: что делать после ответа

Вкладка показывает не «что сделала команда», а **что делать вам**.

- **«Ждут вашего решения»** — три вида: работа упёрлась в ваше решение, вопрос к вам, предложенное решение («Принять» / «Отклонить»). Ответ пишется прямо в строке, кнопка «Ответить»; ответ уходит комментарием и снимает блокировку.
- **«Следующие шаги»** — план руководителя: 3–7 конкретных шагов с исполнителем и сроком.
  - **галочек у вас нет.** Выполнение отмечает руководитель (или система по факту готовых карточек): «Дальше» — предстоящие, «Сделано» — выполненные, «Снято» — снятые вашим ответом. Подпись блока: «План руководителя на ближайшее время. Можно поправить любой шаг».
  - **нажмите на шаг** — откроется окно: что за шаг, исполнитель с подписью профиля и срок, **зачем он нужен** (из какого вопроса/ответа возник), статус и история. Действия: **«Согласен»**, **«Прокомментировать»** (можно надиктовать), **«Переместить»** (срок, исполнитель, выше/ниже), **«Не согласен — убрать»**. Любое действие уходит руководителю как ответ на этот шаг, и видно его реакцию: «принято / учтено / срок изменён / шаг убран»;
  - шаг, противоречащий вашему ответу на вопрос, помечен «противоречит вашему ответу» и его можно убрать сразу из строки;
  - **«В календарь»** — файл `.ics` с одним событием; **«Все в календарь (.ics)»** — один файл со всеми предстоящими шагами со сроком. Открывается любым календарём, интернет не нужен.
- **«Будущие вопросы»** — вопросы «на потом». Кнопка «Задать» превращает вопрос в новый запрос.
- **«Повестка»** — что по срокам на ближайшие две недели.
- **«Закрытые»** — выполненные шаги.

Если действие по шагу не отправилось, приложение скажет человеческое: «Не удалось отправить действие по шагу, обновите страницу и попробуйте ещё раз».

## 8. Где лежат файлы

Два места, и у каждого своя роль.

### Папка проекта — результаты

`<папка проекта>\<дата> <название запроса>\` — отчёты, таблицы, документы, черновики. Плюс `<папка проекта>\README.md` — содержание, обновляется само.

Если папка не задана, команда складывает итоговые файлы в заметки проекта (папка `Материалы`). Лучше задать папку: тогда всё в одном месте и открывается одной кнопкой **«Открыть папку проекта»**.

### Obsidian — память и смысл

В хранилище заметок (Obsidian) приложение ведёт зеркало комнаты: читать удобно, ссылки работают, всё по-русски.

| Что | Где |
|---|---|
| Состояние комнаты | `Rooms/<папка комнаты>/STATE.md` |
| Хронология | `Rooms/<папка комнаты>/Журнал.md` |
| Выжимка для команды | `Rooms/<папка комнаты>/CONTEXT.md` — суть, этап, решения, открытые вопросы, последние запросы, словарь, «где искать» |
| Особые указания | `Rooms/<папка комнаты>/Указания участникам.md` |
| Запрос | `Rooms/<папка комнаты>/Запросы/<дата> <название> (<id>).md` — текст запроса, весь диалог, ответ, шаги, вопросы, решения, артефакты, кто что делал |

Заметки обновляются сами: после каждого ответа и каждого сообщения. **Ваши правки не затираются**: служебные части лежат между невидимыми маркерами, всё написанное вне них сохраняется.

Для команды Obsidian — источник правды: перед работой агенты читают `CONTEXT.md` и заметки по теме, а не спрашивают вас о том, что уже записано.

Куда именно пишет приложение: **Настройки → «Здоровье»** — пути «Данные» и «Заметки» с кнопками «Копировать» и «Открыть».

## 9. Лимит модели: что делать

Лимит — не поломка. Это ограничение подписки на модели: в какой-то момент провайдер говорит «хватит на сегодня».

Что вы увидите:

- у направления статус **«Ждёт лимит»** и подпись «Упёрлось в лимит модели — продолжится само, когда лимит снимется»;
- остальные направления **не стартуют**, чтобы не тратить остаток зря;
- запрос целиком может встать на паузе, ничего не потеряв.

Что делать:

1. **Подождать.** Очередь сама продолжит работу, когда лимит отпустит. Перезапускать и нажимать «Запустить» заново не нужно.
2. **Уменьшить нагрузку.** Настройки комнаты → «Одновременно направлений» → 1. Меньше параллельных работ — меньше расход.
3. **Отложить лишнее.** «Отложить» у направлений, которые могут подождать. Вернуть — «Запустить».
4. **Посмотреть, сколько осталось.** В Hermes: `hermes usage` — лимиты, `hermes insights --days 7` — расход по сессиям.
5. **Не гнать работу вручную.** «Разложить сейчас» и повторные «Повторить» — тоже обращения к модели; при лимите они только тратят остаток.

Приложение денег не считает и не делает вид, что считает: расход зависит от моделей участников и длины контекста.

## 9.1 «Проверить доску сейчас»: не ждать минуту

Диспетчер Hermes сам смотрит на доску раз в минуту и запускает готовые задачи. Кнопка
**«Проверить доску сейчас»** делает один такой проход сразу — она нужна, когда задача готова,
а исполнитель не стартует.

Где она есть: блок «Свод команды» на странице запроса, меню «Действия» этого запроса и
«Настройки» → «Здоровье». Название и подсказка одинаковые везде: «Не ждать минутного
таймера — запустить готовые задачи».

После нажатия появляется панель с итогом, а не только «готово»:

- «Запущено 2 исполнителя: Юрист — Юр-проверка ИП, Операции — смета упаковки»;
- «Возвращено зависших: 1» — работы, которые не отвечали, вернулись в очередь;
- «Переведено из ожидания в готовые: 2» — запустятся сами в течение минуты;
- «Запускать нечего» — и объяснение: сколько работ уже идёт, сколько ждёт вашего ответа,
  сколько ждёт других задач.

Кнопка показывается только тогда, когда есть что запускать (готовые к запуску или зависшие
работы). Если её нет — рядом написано, почему: «Проверять доску сейчас не нужно: 3 уже идут,
1 ждёт вашего ответа». Чаще раза в 30 секунд проход не запускается — приложение честно скажет,
через сколько секунд можно повторить.

## 10. Остальные вкладки коротко

**«Команда»** — карточки участников: роль в комнате, описание, модель, живой статус, текущая работа. Здесь же «Добавить», «Убрать», строка «Особые указания». Участники «вне состава» (движок позвал кого-то, кого нет в комнате) помечены предупреждением — лечится «Переназначить» в дереве работ.

Рядом с выбранной моделью теперь стоит вторая подпись — **«ушло на: провайдер · модель · уровень»**: на чём работа реально выполнялась (подтверждено из запуска агента, а не из настроек). Если она расходится с выбором комнаты, рядом появляется пометка **«расходится с выбором комнаты»** — значит, карточка поехала не на той модели; приложение такую карточку останавливает и возвращает на выбранную, запись об этом есть в «Журнале». Та же подпись — у каждой задачи в дереве работ.

**«Карта проекта»** — сверху «Направления» (карта), ниже этапы проекта: текущая фаза, «готово N из M», решения с фильтром «Все / Принято / Предложено». Кнопка «Свести в систему» просит руководителя собрать накопленное в актуальное состояние.

**«Отчёты»** — галерея интерактивных отчётов комнаты. Отчёт не картинка: таблицы сортируются, графики живые, связи можно двигать. Есть «Экспорт HTML» (один автономный файл) и «Печать» (она же сохранение в PDF).

**«Журнал»** — хронология комнаты по дням, включая правки карты руководителем (что и почему). Фильтр, поиск, «Показать ещё 50».

**Поиск и `Ctrl+K`** — палитра: новый запрос, создать комнату, перейти во вкладку, сменить тему, настройки, поиск по всему приложению. Отдельный экран поиска ищет по запросам, решениям, шагам, журналу и отчётам.

**Настройки** — «Здоровье» (движок, доска, пути, кнопка «Проверить доску сейчас»), «Внешний вид», «Уведомления», «Диктовка и словарь», «Вопросы и ответы», «Горячие клавиши», «Новая комната».

## 11. Вопросы и ответы

| Вопрос | Ответ |
|---|---|
| С чего начать новый проект? | Создайте комнату, задайте папку проекта, напишите главный запрос с галочкой «Это бриф проекта». Дальше — карта и «Запустить». |
| Где ответ? | Страница запроса, блок «Ответ» вверху. В ленте у готового запроса чип «готово». |
| Что делать после ответа? | Вкладка «Дальше»: шаги, вопросы, решения. Тот же блок есть на странице запроса. |
| **Что если агент ошибся?** | Четыре пути, по возрастанию силы: (1) **«На доработку»** с замечанием — руководитель перепишет ответ; (2) **сообщение в диалоге** — «это неверно, проверь по документу X»: руководитель передаст тому, кто отвечал; (3) **«Переназначить»** карточку в дереве — работу сделает другой участник; (4) **«Повторить»** на упавшей карточке. И главное: факты всё равно проверяйте. Система гарантирует, что ответ собран из работы команды и прошёл (или не прошёл) критика, — она не гарантирует истинность. |
| **Как изменить карту голосом?** | Откройте бриф → «Диалог по запросу» → надиктуйте, что поменять → «Отправить руководителю». Сроки, ответственных и состав он применит сам; новые направления появятся как «Предложено» и ждут «Запустить». |
| Команда пошла не туда | Галочка «Срочно: пересмотреть план целиком» в диалоге. Ничего не останавливается, руководитель пересматривает оставшиеся работы. |
| Что от меня ждут? | Бейдж «Ждёт тебя» у комнаты слева, блок «Ждут вашего решения» внутри. Ответить можно прямо в строке. |
| На каком мы этапе? | «Карта проекта»: направления, фазы, решения. Текущая фаза — чипом в шапке комнаты. |
| Почему ничего не происходит? | По порядку: «Здоровье» → движок, кнопка «Проверить доску сейчас» (один проход диспетчера: запускает готовые задачи, не дожидаясь минуты, и показывает, что именно запустилось и кто чего ждёт); запрос «в очереди» → «Разложить сейчас»; направления «Ждёт лимит» → подождать или уменьшить параллельность; все карточки «blocked» → ответить в «Ждут вашего решения». |
| Куда команда кладёт файлы? | В папку проекта, подпапку этого запроса. Суть — в заметку Obsidian. См. раздел 8. |
| Как добавить участника? | «Команда» → «Добавить». Новый участник сразу доступен руководителю. |
| Как поменять руководителя? | Открыть комнату → «Изменить» → «Руководитель комнаты». Новый будет раздавать работу со следующего запроса. |
| Можно без критика? | Да: в комнате «Без критика» или снять «С критиком» у конкретного запроса. Ответ придёт сразу после свода. |
| Что делает критик? | Читает запрос и свод и отвечает «принято» или «на доработку» со списком замечаний. При «на доработку» руководитель делает новую версию. Сколько раундов — задано в комнате: 1, 2 или «до полного одобрения». |
| Что такое раунд критика и сколько ставить? | Раунд — один цикл «критик проверил → если нашёл замечания, исполнители доработали → снова проверили». 1 раунд — быстро; 2 раунда — тщательнее, у команды есть вторая попытка. «До полного одобрения» — цикл идёт, пока критик не скажет «принято»: удобно оставить на ночь. Страховки: остановка, если замечания повторяются три раунда подряд; пауза при лимите провайдера; потолок раундов (по умолчанию 12) с понятным отчётом. Выбирается в комнате («Изменить» → «Раунды проверки») и на странице запроса. |
| Почему руководитель больше не спрашивает про раунды? | Число раундов задаётся один раз в комнате: руководитель получает его в своём задании и не переспрашивает. Если такой вопрос всё же появился в старом запросе, приложение его скрывает, а в журнале комнаты пишет, что значение уже задано. |
| Как попросить интерактивный отчёт? | Скажите в запросе прямо: «сделай интерактивный отчёт с таблицей и графиком». Он появится во вкладке «Отчёты» и на странице запроса. |
| Хочу в календарь | «Дальше» → у шага есть срок → «В календарь» (`.ics`). Прямой записи в календарь приложение не делает. |
| Хочу послать результат | Экспорт `.md` и автономный `.html` со страницы запроса: один файл, всё внутри. |
| Можно диктовать длинно? | Да — до 10 минут одной записью (лимит из настроек Hermes), и текст может быть очень большим. Длинная запись сохраняется частями, поэтому обрыв окна или сети её не теряет: появится «Распознать запись». |
| Что было раньше по теме? | `Ctrl+K`, вкладки «Журнал» и «Карта проекта», экран поиска. |
| Кто-то изменил мои заметки? | Никто: приложение пишет только служебные части между маркерами, ваши правки вне них не трогает. |
| Сколько это стоит? | Приложение не считает деньги. Расход — модели участников и длина контекста: `hermes insights --days 7`. |

### Что система может и чего не может

**Может:** принять главный запрос и разложить его на направления; провести каждое направление через команду; собрать шаги, вопросы, решения, фазы; сделать интерактивный отчёт; отдать `.ics`, `.md`, автономный `.html`; держать папку проекта и заметки в Obsidian в актуальном состоянии; найти прошлое поиском.

**Не может (и это осознанно):**

- **Гарантировать состав исполнителей.** Разбор делает движок Hermes, а не приложение: он может позвать профиль вне состава комнаты. Приложение это покажет и даст переназначить.
- **Писать в календарь напрямую.** Только файл `.ics`.
- **Работать без Hermes.** Нет базы задач или движка — приложение покажет диагностику и честно скажет, чего не хватает.
- **Работать с мессенджерами.** Только локальный браузер (или страница внутри Hermes Desktop).
- **Проверять факты за вас.** Цифры, которые команда не подтвердила файлом, остаются цифрами из модели.
- **Считать деньги и сроки за вас.** Длительности работ есть, стоимости нет.

## 12. Если что-то не так

Сначала два места, где всегда видно правду: **Настройки → «Здоровье»** и логи в `data\logs\`:

| Файл | Что там |
|---|---|
| `data\logs\app.log` | приложение и фоновые проверки: ошибки приёма ответов, заметок, отчётов |
| `data\logs\engine.log` | обращения к Hermes: время, длительность, код возврата, команда (без текста) |

Пути к данным и заметкам есть в «Здоровье» — там же кнопки «Копировать путь» и «Открыть».

| Симптом | Что проверить | Что сделать |
|---|---|---|
| «Движок не запущен» | «Здоровье»: состояние движка, когда обновлялся | движок живёт внутри Hermes: `hermes gateway status`, при необходимости `hermes gateway ensure`, потом «Проверить доску сейчас» |
| Порт занят: «Порт 8777 занят…» | не открыто ли второе окно приложения | закройте старое окно (`Ctrl+C`) или запустите `python server\app.py --port 8788` и откройте `http://127.0.0.1:8788` |
| Белый экран | адрес в строке браузера | откройте именно `http://127.0.0.1:8777` (не файл с диска), обновите `Ctrl+F5` |
| Ответ не появляется | статус запроса, «Дерево работ», «Здоровье» | «в очереди» → «Разложить сейчас»; «blocked» → ответить в «Ждут вашего решения»; движок стоит → поднять; «ошибка» → «Повторить» |
| Направления не стартуют | статус у направлений | «Предложено» → нажмите «Запустить»; «Ждёт лимит» → подождите; «В очереди» → проверьте зависимости и «Одновременно направлений» |
| Карта пустая | включён ли проектный режим; был ли бриф | включите проектный режим; отправьте главный запрос с галочкой «Это бриф проекта» |
| Отчёт пустой | просили ли отчёт явно | попросите в новом запросе «сделай интерактивный отчёт…» или отправьте на доработку с замечанием «отчёт пустой» |
| Микрофон не пишет | разрешение, занят ли другими программами | раздел 2, последняя таблица |

Если ничего не помогло — закройте окно сервера и запустите заново. Данные не пропадут: они в `data\` и в задачах Hermes.

## 13. Словарь

| Слово | Что это значит на практике |
|---|---|
| **Комната** | Рабочее пространство под один проект: свой руководитель, состав, критик, карта, папка. Переключается слева. |
| **Запрос** | Один текст от вас. У него есть статус, дерево работ и один сводный ответ. |
| **Бриф** | Главный запрос проекта: «разложи, что нужно сделать». Ответ на бриф — карта направлений. |
| **Направление** | Кусок большого проекта, который команда делает отдельно: своё название, ответственный, срок, статус. |
| **Карта** | Все направления проекта и порядок между ними. |
| **Руководитель комнаты** | Участник, который раздаёт работу и сводит один ответ. Получает ваши сообщения первым. |
| **Критик** | Участник, который проверяет свод: «принято» или «на доработку» с замечаниями. |
| **Версия ответа** | Каждый новый свод после доработки — новая версия. Старые хранятся: можно сравнить. |
| **Папка проекта** | Одно место для результатов работы комнаты. |
| **Заметки (Obsidian)** | Зеркало комнаты текстом: состояние, журнал, заметка на каждый запрос, выжимка для команды. |
| **Движок** | Часть Hermes, которая берёт задачи из очереди и запускает участников. Без него работа не начинается. |
| **Лимит модели** | Ограничение подписки на модели. Направление ждёт и продолжается само. |
| **Особые указания** | Добавка к роли участника, действующая только в этой комнате. |
| **Песочница** | Режим для проверок: всё пишется во временные папки, настоящие данные не трогаются. В обычной работе выключена. |
